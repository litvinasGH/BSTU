# ЛР 8 — Hive для исходной социальной сети ЛР 4–5

## Важное про интерфейс

За основу взята исходная ЛР 4–5. Тематика и существующая компоновка экранов сохранены: лента постов, истории, профиль, нижняя навигационная панель, экран камеры и остальные исходные экраны.

На карточке публикации добавлена только кнопка лайка/избранного. Остальные функции ЛР 8 открываются на отдельных экранах:

- существующая кнопка `…` рядом с `Recently Post` открывает экран управления;
- существующая кнопка `+` открывает отдельную форму создания публикации;
- экран управления позволяет переключать тестового пользователя/роль, редактировать и удалять публикации, перейти в избранное и к проверкам Hive;
- проверка неправильного ключа выполняется на отдельном временном Box и не изменяет основную базу.

## Содержимое

- `lib/` — исходные файлы интерфейса ЛР 4–5 с минимальными изменениями для подключения Hive и лайка;
- `lib/models/social_models.dart` — модели и адаптеры Hive;
- `lib/data/hive_social_store.dart` — зашифрованные Box, роли, CRUD, избранное, compaction и демонстрация неправильного ключа;
- `lib/screens/` — отдельные экраны для формы публикации, управления, избранного и диагностики;
- `test/lab8_hive_test.dart` — автоматические тесты основных требований;
- `Ответы_на_вопросы_Hive.md` — ответы на 17 теоретических вопросов.

## Подключение к твоему проекту

Архив `lib4.zip`, который был доступен для работы, содержал исходники `lib/`, но не содержал файлы изображений, платформенные каталоги и полный `pubspec.yaml`. Поэтому оригинальные изображения не подменяются заглушками и не включены в этот архив.

1. Сделай резервную копию своего проекта.
2. Скопируй каталог `lib/` из этого результата в проект ЛР 4–5. Сохрани свои каталоги `assets/`, `android/`, `ios/` и прочие платформенные файлы.
3. В существующем `pubspec.yaml` добавь зависимости, не удаляя текущие настройки и assets:

```yaml
dependencies:
  hive: ^2.2.3
  hive_flutter: ^1.1.0
  path_provider: ^2.1.5
  image_picker: ^1.1.2

dev_dependencies:
  flutter_test:
    sdk: flutter
```

4. Проверь, что `pubspec.yaml` по-прежнему объявляет используемые исходной лабораторной ресурсы: `assets/mainavatar.jpg`, каталог `assets/postsAndStor/` и каталог `assets/splitanimage/`.
5. Выполни команды из корня проекта:

```bash
flutter pub get
flutter test test/lab8_hive_test.dart
flutter analyze
flutter run
```

## Что проверяют тесты

1. Исходные авторы публикаций, истории и тестовые роли загружаются в Hive.
2. Пользователь без прав менеджера не может создавать/удалять публикации, а менеджер может.
3. Избранное связано с ID пользователя и может быть включено/выключено.
4. Вызов `compact()` не удаляет сохранённые публикации.
5. Неправильный ключ не позволяет прочитать тестовую запись, а основная запись остаётся доступной.

## Примечания

- Ключ шифрования создаётся автоматически и хранится во внутреннем каталоге приложения. Не удаляй его при наличии важных зашифрованных данных.
- Основные Box `users`, `posts`, `stories` и `favorites` зашифрованы. Box `settings` хранит только ID выбранного тестового пользователя.
- Роли демонстрационные, без реальной регистрации и аутентификации: это соответствует формулировке лабораторной, в которой допускается переключение пользователя через выбор из списка.
- В этой среде Flutter SDK отсутствовал, поэтому тесты нельзя было фактически запустить здесь. Запускай команды выше в своём проекте и исправляй ошибки, если они проявятся с твоей версией Flutter.

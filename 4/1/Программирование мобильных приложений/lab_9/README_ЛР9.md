# Лабораторная работа №9 — Provider

## Что изменено

- Добавлен `lib/providers/social_provider.dart` — `SocialProvider extends ChangeNotifier`.
- В `main.dart` состояние подключается через `MultiProvider` и `ChangeNotifierProvider`.
- `SocialProvider` подписан на `watch()` всех общих Hive Box: пользователей, публикаций, историй, избранного и настроек. При изменении Box вызывает `notifyListeners()`.
- Удалены старые `ValueListenableBuilder` для общего состояния. Виджеты читают данные через `context.watch<SocialProvider>()`.
- Изменение общего состояния выполняется через `context.read<SocialProvider>()`: выбор пользователя, сохранение/удаление публикации и изменение избранного.
- Передача состояния между независимыми ветками: `NewsFeedHeader` отображает активного пользователя, а соседний `PostFeed` использует тот же `activeUserId` для избранного. Оба виджета находятся ниже `MultiProvider` и получают один экземпляр `SocialProvider`.

## Что оставить через setState и почему

`setState` остался только для состояния конкретного экрана/виджета, которое не требуется передавать другим веткам дерева:

- значения гироскопа и смещение параллакс-эффекта в `NewsFeed`;
- локальное значение заряда батареи в `BatterPage`;
- выбранная фотография в `CameraPage`;
- выбранная вкладка, поисковая строка и порядок сортировки в `SocialHomeScreen`;
- индикатор выполнения и текст результата в `HiveDiagnosticsScreen`;
- локальный счётчик уведомления в `NewsFeedHeader`.

Эти поля не являются общим состоянием приложения. Поля, связанные с пользователем, публикациями, историями и избранным, в `setState` не изменяются.

## Подключение зависимости

В существующем `pubspec.yaml` внутри секции `dependencies` добавьте:

```yaml
provider: ^6.1.5+1
```

Затем из корня Flutter-проекта выполните:

```bash
flutter pub get
flutter analyze
flutter run
```

Архив, из которого выполнялась работа, содержал только каталог `lib/`. Поэтому готовый архив также содержит обновлённый `lib/`, а не полный Flutter-проект: исходный `pubspec.yaml`, `assets/`, платформенные папки и остальные файлы проекта в предоставленном архиве отсутствовали.

## Проверка требований задания

| Требование | Реализация |
|---|---|
| Взять приложение из лабораторной №8 | Использована переданная папка `lib/` |
| Заменить управление общим состоянием на Provider | Единый `SocialProvider`, убраны Hive `ValueListenableBuilder` из экранов |
| Локальное состояние можно оставить на setState | Оставлены только локальные поля экранов, обоснование выше |
| `ChangeNotifierProvider` | Используется в `main.dart` |
| `MultiProvider` | Используется в `main.dart` |
| `Consumer` или `context.watch/select` минимум в двух местах | `context.watch` используется в `NewsFeedHeader`, `PostFeed`, `StoriesFeed`, `SocialHomeScreen`, экранах избранного и управления |
| `context.read` для методов | Используется в обработчиках действий |
| Обмен данными между несвязанными виджетами | `NewsFeedHeader` и `PostFeed` читают общий `SocialProvider` |
| Не использовать setState для данных Provider | Общее состояние изменяется методами `SocialProvider`; локальные `setState` оставлены отдельно |

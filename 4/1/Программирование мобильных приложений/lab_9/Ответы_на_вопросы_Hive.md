# Ответы на вопросы к ЛР №8 «ORM Hive»

## 1. Чем Hive отличается от SQFLite? Когда что выбирать?

Hive — локальное NoSQL key-value хранилище: данные сохраняются в Box по ключам, запросы обычно выполняются по значениям и в памяти. Оно удобно для настроек, кэша и небольших локальных объектов. SQLite/SQFLite — реляционная база с таблицами, SQL, JOIN, индексами и транзакциями; она лучше подходит для сложных выборок и связей между большим количеством сущностей.

## 2. Как Hive обеспечивает типобезопасность?

При объявлении `Box<SocialPost>` API ожидает значения типа `SocialPost`. Для пользовательских классов нужен зарегистрированный `TypeAdapter`, который сериализует и восстанавливает поля. Использование нетипизированного `Box` ослабляет проверки на этапе компиляции.

## 3. Что такое адаптер в Hive и зачем он нужен?

`TypeAdapter<T>` переводит объект `T` в бинарное представление при записи и восстанавливает объект при чтении. В проекте собственные адаптеры используются для `SocialUser`, `SocialPost`, `SocialStory` и `FavoriteEntry`. ID адаптеров должны быть уникальными и оставаться неизменными после появления сохранённых данных.

## 4. Как работает шифрование в Hive? Где хранится ключ?

Box открывается с `encryptionCipher: HiveAesCipher(key)`. Hive шифрует и расшифровывает данные прозрачно для обычных операций `put/get`. Ключ должен быть стабильным между запусками и недоступным другим приложениям. В этом учебном решении ключ хранится в отдельном файле во внутреннем каталоге приложения; в production лучше использовать системное защищённое хранилище.

## 5. Как сжатие влияет на производительность и размер?

Нужно отличать сжатие содержимого от `compact()`. Уплотнение переписывает файл Box и убирает место, оставшееся после заменённых/удалённых записей. После уплотнения файл может стать меньше, но сама операция требует ввода-вывода и процессорного времени и может ненадолго задержать приложение. В этом проекте используется `compact()`, а не ZIP-сжатие.

## 6. Что такое `compactionStrategy`?

Это функция, по которой Hive решает, пора ли автоматически уплотнить Box. Она получает число записей и число удалённых/устаревших записей и возвращает `true` или `false`. В проекте уплотнение рекомендуется, когда есть хотя бы 20 устаревших записей и их доля достигает 20% от количества записей.

## 7. Как Hive работает с изолятами?

Обычные Box используются в том изоляте, где они были открыты; обычный доступ к одному объекту Box не следует считать автоматически потокобезопасным между изолятами. Для тяжёлых вычислений можно передавать сериализуемые данные в отдельный isolate, а для реализаций Hive CE есть отдельный API изолированного доступа. Небольшому приложению социальной сети из этого задания отдельные изоляты не требуются.

## 8. Как мигрировать данные при изменении схемы?

Нужно сохранять стабильными ID адаптеров и номера полей; существующие номера полей нельзя повторно назначать другим значениям. Новые поля добавляют с безопасными значениями по умолчанию. Для более серьёзного изменения выполняют версионированную миграцию: читают старые записи, преобразуют их, записывают в новую схему и удаляют старые данные только после успешной проверки миграции.

## 9. Чем `Hive.openBox()` отличается от `Hive.openLazyBox()`?

Обычный Box загружает значения в память и обеспечивает быстрый частый доступ. LazyBox хранит значения на диске и загружает их при обращении асинхронно; он полезен, когда данных много или отдельные значения крупные и не нужны одновременно. Для небольшого списка публикаций подходит обычный Box.

## 10. Как хранить список объектов в Hive? Какие ограничения?

Можно хранить список поддерживаемых Hive значений в одном Box или сохранять каждый объект отдельной записью. Для пользовательских типов должны быть зарегистрированы адаптеры. Если список хранится внутри объекта, после изменения списка нужно записать изменённый объект обратно в Box. Отдельные записи обычно удобнее обновлять и удалять независимо.

## 11. Что произойдёт, если не закрыть Box перед завершением приложения?

Открытый Box обычно остаётся открыт, пока приложение работает. При завершении процесса операционная система освободит ресурсы, но не следует полагаться на это вместо ожидания завершения записей. Записи нужно выполнять с `await`; Box можно явно закрыть, когда приложение больше не должно им пользоваться. В Flutter не всегда есть надёжный callback на принудительное завершение процесса.

## 12. Как удалить все данные из Box? Чем `box.clear()` отличается от `box.deleteFromDisk()`?

`await box.clear()` удаляет записи, но сохраняет сам Box и возможность продолжать пользоваться им. `await box.deleteFromDisk()` закрывает Box и удаляет его файл с диска; после этого при необходимости Box нужно открыть заново. Для очистки только избранного в этой работе предпочтительнее удалять отдельные записи или вызвать `clear()` именно у Box избранного.

## 13. Как реализовать поиск и сортировку данных в Hive? Сравните с SQFLite.

В Hive можно получить `box.values`, применить `where`, преобразовать результат в список и отсортировать через `sort`. В интегрированном проекте лента сортирует публикации по времени, а фильтрацию можно реализовать через `box.values.where(...)`. Такие операции выполняются в памяти; у SQLite поисковые и сортировочные операции можно выполнять через SQL, использовать индексы и эффективнее масштабировать сложные выборки.

## 14. Как ограничить доступ к CRUD-операциям в зависимости от роли пользователя?

Роль пользователя хранится в модели, например `admin`, `manager`, `user`. UI скрывает кнопки редактирования для обычного пользователя, но этого недостаточно: методы бизнес-логики тоже должны проверять роль до записи или удаления. В проекте `HiveSocialStore.savePost()` и `deletePost()` повторно проверяют роль. Переключение роли в учебном приложении — демонстрация, а не полноценная система аутентификации.

## 15. Как связать избранное с конкретным пользователем? Приведите структуру данных.

У каждой записи избранного есть `userId`, `postId` и дата добавления. Ключ записи строится как `userId::postId`. Так одна и та же публикация может быть добавлена разными пользователями независимо. При удалении публикации связанные записи избранного удаляются.

## 16. Какие данные нельзя хранить в Hive? Приведите примеры.

Не стоит хранить пароли в открытом виде, приватные ключи, секреты API и токены без отдельной защиты, а также полагаться только на локальный Box для секретов, которые должны быть защищены от владельца устройства. Большие изображения/видео лучше хранить отдельными файлами, а в Hive — их путь и метаданные. Шифрование Box не заменяет разграничение доступа, резервное копирование и серверную авторизацию.

## 17. Как Hive работает с асинхронностью? Нужно ли использовать изоляты?

Запись и операции с файлами выполняются асинхронно, поэтому результат следует ожидать через `await`; это позволяет не блокировать интерфейс во время ввода-вывода. Изоляты нужны при тяжёлых вычислениях, которые могут занять UI isolate, но обычные CRUD-операции с небольшим локальным Box, как в этой работе, не требуют отдельного isolate.
